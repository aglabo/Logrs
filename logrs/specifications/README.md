Logrs DSL は、**ドメインの構造を記述するための汎用言語** です。本書はその **llm 向け半形式仕様** です。

**本 DSL は実行を目的としません。llm との認識共有を目的とします。**

## v0.8.0 の変更

**仕様が自分自身の文法を通るようにしました。** 字句クラスの修正と `<block-kind>` の緩和という 2 つの BNF 変更、および規範どうしの矛盾の解消です。あわせて、同種の齟齬が再発しないよう機械検証を CI に載せました。

### 字句クラスが日本語の句読点を弾いていた

`CJK = %x3040-309F / %x30A0-30FF / %x4E00-9FFF` はひらがな・カタカナ・漢字しか含みません。`、` (U+3001)・`。` (U+3002)・`「」`・`…`・`？` `！` は範囲外です。文字列リテラルと heredoc の非 ASCII はこの `CJK` だけを参照していたため、**02〜05 の heredoc の多くが字句エラー** でした。`04` の `rule sentence_delimiter` は句読点を定義する行が句読点を書けず、`01` 自身が示す `%dsl` の模範例も `、` を含んでいました。

`CJK` を廃し、`<non-ascii>` を導入しています。

```abnf
<non-ascii>       ::= %xA0-D7FF / %xE000-FFFD / %x10000-10FFFF
```

あわせて `<identifier>` からは非 ASCII を **外しました**。 [00-overview の設計原則 7](./00-overview.md#設計原則) ・`04` の `constraint identifier_format`・`05` の `character-set` は、いずれも ASCII 限定を要求しています。`<identifier>` に `CJK` を含めていた `01` だけが食い違っていました。日本語は別名 (`-> "…"`) と文字列リテラル・heredoc でのみ書きます。

### `%example` の識別子スロットを 1 個から任意個に

`<block-kind> ::= "%" <identifier> [<identifier>] …` は追加識別子を 1 個しか許しません。v0.7.0 が `%example` の紹介に使った 2 例は、どちらも **自分の BNF に受理されていませんでした**。`%example forbidden normal_flow` と `%example permitted recovery` がそれです。 `*<identifier>` に緩め、`<label-name>` と同じ形にしています。

### 記号トークンの一覧を定めた

`<option>` が使う `--` は、`1.1.3` の最長一致の説明 (`<` `>` `!` `=` 系のみ) に現れず、`-` が `<identifier>` の内部文字でもあるため切り出し規則が決まりませんでした。[記号トークンの一覧](./01-syntax-core.md#記号トークンの一覧) を追加し、`-` と `.` が単独では記号でないことを明記しています。

### 宙に浮いた参照を解消した

- `rule non-processing areas` / `rule non-proofreading areas` — 実体は v0.4.0 に消えたまま、2 通りの名前で参照されていた。削除し、`03` の「二重防護」を単一防壁に書きあらためた
- `:acceptance` — `03` でプロファイルへ移したのに `04` のフォールバック表と `fallback` 定義が使い続けていた。`:session_phase` ベースに置き換えた
- `:session_phase` の値集合が 3 通り (`04` の test は 3 状態、`04` の `/complex` は `processing`、`05` は 4 状態) あった。`command` / `input` / `waiting` に統一した
- 未定義のイベント (`#ProcessFailed` `#ProcessCompleted` ほか) と変数 (`:previous_mode` `:remark`) を `04` の `%define` で定義した。型 `mode` `priority_level`、スコープ `@scoped` も解消した
- 校閲ドメイン固有の `:generation-status` `:status` `:category` をコアから削除した

### `=>` ではじめて遷移表を書いた

`:session_phase` の許可遷移は `;` コメントで「左から右へ遷移可能」と書かれているだけで、`05` が「定義された遷移制約 (`=>`)」を根拠に禁止を宣告する相手が存在しませんでした。[04 の構文要素の意味](./04-semantics-execution.md#構文要素の意味) に `transitions` ブロックを置き、`<transition>` を状態機械の宣言に使っています。

### 仕様自身が破っていた規則を直した

- 「前方参照は許可されない」— `03` が `/begin` `/process` を制約し定義は `04` にある。unit をまたぐ参照を制約の対象外とした
- note の配置「本体の末尾 (文の後、constraint の前)」— 文言自体が矛盾し、`04` は中程に多数置いていた。「本体のどこでもよい」にあらためた
- 再定義禁止 — 同一ブロック内の重複 `note:` を `forward_order` / `backward_order` に分け、`rule constraint composition` の二重定義を解消した
- `04` の `rule composition priority extension` がヘッダから `note:` に降格し、本体だった `status:` 以下が `%rule` 直下に露出していた。ブロックに戻した

### 機械検証を CI に載せた

`scripts/check-spec-syntax.mjs` が `logrs/specifications/*.md` のコードフェンスを走査します。検査項目は、字句クラス外の文字・`<block-kind>` の識別子・リテラル外の非 ASCII・ブロックの対応・未定義シンボル参照です。`pnpm run check:spec` で実行でき、`.github/workflows/ci-spec-check.yml` が PR ごとに走ります。

意図的に非 DSL のフェンス (構文エラーの提示、`→` `≡` を使う評価表) は、直前に `<!-- logrs-check: skip -->` を置いて除外します。

### 残る未達

受理性は回復しましたが、**自己記述の内容の多くはまだ言語の外にあります**。02〜05 のコードフェンス 1666 行のうち 769 行 (46%) が heredoc 本文で、値が単一の文字列リテラルであるラベル定義が 98 箇所あります。

- 集合・列挙・順序つきリストを表す構文がない (`<value>` は単一トークン)。値集合も禁止事項の箇条書きも heredoc の散文になる
- `rule` `constraint` `note` `behavior` など、ラベルの先頭語として使われる 150 種の語に意味を与える構文がない。意味論が定義されているのは `note` だけ
- 条件式が依存する真偽性、`_` と `""` の関係、コマンドパラメータの束縛と参照が未定義

これらは言語機能の追加を要するため、v0.9.0 以降で扱います。

## v0.7.0 の変更

例示を例示として書く手段を用意しました。**統一 BNF は変えていません。** 変更は意味論の定義です。

### 例示ブロック `%example`

仕様は「これは例である」と言う手段を持たず、例示コードが本物の定義としてパースされていました。もっとも悪い例が [05-heuristics](./05-heuristics.md) のアンチパターン節で、禁止例を見せるために heredoc の中に Markdown のコードフェンスだけを詰め、実コードをフェンスの外に置いていました。結果、「禁止例」のイベントハンドラが **有効な定義として登録される** 状態でした。

```text
%example anti_pattern -> "禁止: イベントで状態遷移を実現する" {{
  <-#UserInputReceived {{
    :session_phase <- input
  }}
}}
```

`%example` は `<block-kind> ::= "%" <identifier> [<identifier>] *<modifier> [<alias>]` そのものなので、**新しい文法を足していません**。足したのは意味論で、メタブロックの「定義登録」を種別ごとの性質にあらため、`%example` だけを登録対象から外しました。入れ子には再帰的に伝播します。詳細は [02-syntax-metablock の `%example`](./02-syntax-metablock.md#example--登録されない例示) を参照してください。

### heredoc はネストしない — 例示は heredoc の外に書く

heredoc 本文に `<<<` を含められない制約 ([heredoc](./01-syntax-core.md#heredoc)) は設計として維持します。したがって DSL コードを含む例を heredoc に入れることはできず、**例示は heredoc の外に `%example` で囲んで書きます**。フェンス偽装はこの制約を迂回しようとした結果でした。

### `%dsl` の範囲を定めた

`%dsl` は 6 つのファイルで「DSL 構文定義」と宣言されながら、一度も実体化していませんでした。v0.7.0 では **Syntax 層の生成規則を自己記述の対象外** と定め、ABNF を正規のメタ言語として明示します ([00-overview の設計原則 8](./00-overview.md#設計原則))。`%dsl` が担うのは言語の姿勢と、ABNF では表現できない制約です ([文法の自己記述について](./01-syntax-core.md#文法の自己記述について))。

その制約の本文は heredoc ではなく **文字列リテラル** で書きます。`<<<` を含むテキストは heredoc に入れられませんが、文字列リテラルの内部には字句規則がおよばないため書けます。「heredoc に `<<<` を書けない」という制約を DSL で表明できるのは、この書き分けによります。

### 02 の重複 BNF を削除した

[02-syntax-metablock](./02-syntax-metablock.md) は `<meta-block>` `<block-type>` `<block-content>` という独自の BNF を持っていました。種別を 6 つに閉じており、01 の `<block-kind>` が持つ第 2 識別子・`<modifier>`・`<alias>` を欠いた古い複製で、規範部どうしの矛盾でした。削除して 01 への参照に置き換えています。

### 適用箇所

- `03` の `example alias-usage` と、`04` の 6 箇所、`05` の 8 箇所を `%example` で囲み直した
- `05` からフェンス偽装用のダミー `note` 16 個と、四重バッククォートが消えた
- `01` の `bnf-formality` ブロックを `%dsl` に差し替えた
- `<guard>` に「既定分岐が先行する分岐を要することは ABNF では表現できない」旨の注記を追加した

## v0.6.0 の変更

位階 (順序づけ) を文法に導入しました。位階演算子 `>>` の追加です。

### 位階演算子 `>>`

値の上下関係は、これまで `level_definitions: <<<critical : 即座の対応が必要 …>>>` のように heredoc の散文に置かれていました。散文から位階を復元するには推論が要ります。`>>` は位階を構造として残し、説明文とは別の層に分けます。

```abnf
<rank-def>        ::= <label-name> ":" <rank-chain>
<rank-chain>      ::= <identifier> 1*(">>" <identifier>)
<rank-comparison> ::= <rank-operand> ">>" <rank-operand>
<rank-operand>    ::= <var-name> / <identifier>
```

<!-- logrs-check: skip -->

```text
priority: A >> B >> C >> D >> E        ; 位階軸の宣言
(:severity >> medium) {{ … }}          ; 条件式の項
```

左が上位です。**同位は表現しません** (位階は全順序)。`<<` はありません。詳細は [1.1.5 位階](./01-syntax-core.md#115-位階) と [位階の意味論](./03-semantics-core.md#位階の意味論) を参照してください。

`>` との違いは解決規則です。`>` は両辺を数値として解釈してから比べます。`>>` は宣言された並びの中での位置で比べるもので、値を数値に解釈しません。位階を表すために `1` `2` `3` を振る必要はなくなります。

### 字句の切り出しを前方優先と明記した

最長一致に加えて前方優先であることを明記しました ([1.1.3 字句規則](./01-syntax-core.md#113-字句規則))。左から走査し、その位置で最も長く一致する記号を取り、確定したトークンを後続の文字で取り消しません。`>>=` は `>>` と `=` に切り出します (`>` と `>=` ではありません)。`>>` の追加で `>` 始まりの記号が 3 つになったための明文化です。

### 位階軸ごとに条件式での可否を定める

`04-semantics-execution` の `priority` は「衝突時の選択指針であって適用順序ではない」と定義されており、実行条件の判定に使うことを禁じています。位階として宣言はしますが、条件式の項には置けません。位階軸が条件式で使えるかどうかは軸ごとに定まり、既定では使えます。

### 適用箇所

- `03-semantics-core` の `constraint priority values` (A〜E) を `priority: A >> B >> C >> D >> E` に上げ、説明は説明層に残した
- `04-semantics-execution` の `priority` ブロックに `level: critical >> high >> medium >> low` を置き、`level_definitions` の説明文はそのまま残した

## v0.5.1 の変更

BNF は変えていません。02〜05 の記述を v0.5.0 の文法に合わせた修正だけです。

- 添字記法 `alias-map[command]` を実行文にあらためた (03)
- `rule /begin:` のようにラベル名へ sigil を置いていた箇所を、コマンド名を値側に移して解消した (03)
- `:execute_mode: idle => processing` を代入 `:execute_mode <- processing` にあらためた (03)
- `clearby: /exit` など、コマンド名を裸で値に置いていた箇所を文字列リテラルにした (03)
- 裸の識別子への代入に変数 sigil を補った (04)
- CJK で始まる識別子を、[別名](./01-syntax-core.md#12-統一-bnf) (`-> "…"`) または文字列リテラルに置き換えた (04)
- 将来予約の記法 `+/cmd ^ --priority:` を heredoc に落とし、現行文法の解釈対象から外した (04)
- alias-line の直後に `:` を置いていた箇所をブロックにあらためた (05)

## v0.5.0 の変更

自己記述 ([四層構造](#四層構造)) を成立させるための修正です。言語の姿勢は v0.4.0 から変えていません。

### 見出し語を複数の語で書ける

`<label-name>` を新設し、`<label-def>` と `<named-def>` の名前部分をこれに置き換えました。`constraint status values:` や `rule composition constraint composition {{` のように、種別と名前を空白で連ねた見出しが文法に含まれます。末尾には数値も置けます (`test_case 1:`)。

```abnf
<label-name>      ::= <identifier> *(<identifier> / <number>)
<named-def>       ::= <label-name> [<payload>] *<modifier> [<alias>]
<label-def>       ::= <label-name> ":" <value>
```

v0.4.0 の `<identifier> [<identifier>]` では、02〜05 の見出しの大半が受理されませんでした。

### 条件ガードの散文を引用で囲んだ

v0.4.0 で [自由文を廃止](./01-syntax-core.md#自由文の廃止) したにもかかわらず、02〜05 には `(処理が完了した) {{` のような終端を持たない条件が残っていました。これらを `("処理が完了した") {{` と文字列リテラルの項にあらためています ([1.1.4 条件分岐](./01-syntax-core.md#114-条件分岐))。あわせて、ガードの直後が `{{` ではなく `:` になっていた箇所をブロックに直しました。

## v0.4.0 の要点

### レイアウトに意味はない

空白 (SP)・水平タブ (HTAB)・改行 (LF / CR) は、**すべて等価なトークンの区切り** です。種類・個数・位置のいずれも解釈を変えません。字下げ・行頭・行末にもとづく規則はありません。

改行だけは、区切りであることに加えて 3 つの役割を持ちます。コメントを終端すること、文字列リテラルの内部に現れてはならないこと、heredoc の開始直後の 1 個が捨てられること。この 3 つがすべてで、いずれも 1 つのトークンの切り出し方の規則です。文やブロックの境界は改行と無関係に決まります。

```text
%define {{
  /begin -> "入力モード開始" {{
    :buffer        <- _
    :session_phase <- input
  }}

  <-#ProcessFailed {{
    ! "セッションを停止する"
  }}
}}
```

```text
; 上とまったく同じ構文木
%define {{ /begin -> "入力モード開始" {{ :buffer <- _ :session_phase <- input }}
<-#ProcessFailed {{ ! "セッションを停止する" }} }}
```

### 構造は記号、散文は引用

構造をすべて ASCII 記号が担うため、**予約語がありません**。英単語は一語残らずラベル・識別子として自由に使えます。自然言語による記述は必ず `"..."` `'...'` `<<<` で囲みます。単一行なら文字列リテラル、複数行なら heredoc です。

| 記号                | 役割                                                                      |
| ------------------- | ------------------------------------------------------------------------- |
| `{{` / `}}`         | ブロックの開始と終端。配置は自由                                          |
| `<-`                | 代入 (右辺 → 左辺)                                                        |
| `->`                | 別名・対応付け                                                            |
| `=>`                | 状態遷移                                                                  |
| `==` `!=`           | 比較 (等値 / 非等値)。値は文字列として比べる                              |
| `<` `<=` `>` `>=`   | 比較 (大小)。両辺を数値として解釈する。文字列どうしの大小比較は定義しない |
| `_`                 | 空値・未定義・既定                                                        |
| `%` `/` `:` `#` `@` | ブロック種別 / コマンド / 変数 / イベント / スコープ                      |
| `!`                 | 実行 (`! "指示"`) と発火 (`!#event`)                                      |
| `+`                 | 合成 (`+/cmd ^`) と付加指定 (`+location`)                                 |
| `(条件)`            | 条件分岐のガード                                                          |
| `!` `&` `\|`        | 条件式の論理演算 (not / and / or)。`!` が最優先、`&` と `\|` は同一優先度 |
| `; …` + 改行        | コメント。改行までが 1 つのコメント                                       |
| `"..."` `'...'`     | 文字列リテラル。単一行のみ。改行をまたげない                              |
| `<<<` … `<<<`       | heredoc。複数行のテキストを書ける唯一の記法                               |

記号の完全な一覧は [01-syntax-core の記号体系](./01-syntax-core.md#11-記号体系) を参照してください。

### ドメインはコアから分離した

v0.3.0 までコア仕様に含まれていた校閲レビュー向けの定義 (Part 3 / Part 4) は、v0.4.0 で削除しました。コア仕様はドメインを持ちません。

ドメイン固有の語彙は、コア仕様の上に置く **プロファイル** が定義します。プロファイルはコア仕様が固まったのち、あらためて作成します。

## 読み方

| 立場               | 読む順序          |
| ------------------ | ----------------- |
| はじめて読む       | 00 → 01 → 02 → 03 |
| DSL を書く         | 00 → 01 → 05      |
| ドメインを定義する | 01 → 03 → 04      |
| 実装する           | 01 → 03 → 04      |

## 四層構造

1. **Overview** (00) — 設計原則と全体像
2. **Syntax** (01, 02) — BNF による文法定義
3. **Semantics** (03, 04) — 形式意味論
4. **Heuristics** (05) — スタイル指針

この 4 層がコア仕様です。ドメイン語彙はコア仕様の外側、プロファイルが担います。

Semantics と Heuristics は、Syntax が定義する構文そのもので記述します (自己記述)。**Syntax 層の生成規則は自己記述の対象外** であり、ABNF を正規のメタ言語とします ([00-overview の設計原則 8](./00-overview.md#設計原則))。

例示の隔離は v0.7.0 の [`%example`](./02-syntax-metablock.md#example--登録されない例示) で、[1.2 統一 BNF](./01-syntax-core.md#12-統一-bnf) による受理性は v0.8.0 で解決しました。`pnpm run check:spec` が 02〜05 のコードフェンスを機械検証しています。

残る未達は言語機能の不足です。コードフェンスの 46% が heredoc 本文であり、構文が担っているのは容器だけで内容はほぼ自然言語です ([v0.8.0 の残る未達](#残る未達))。

## バージョン管理 (Semantic Versioning)

本仕様は 0.0.1 を起点とし、1.0.0 未満の開発段階にあります。

- MINOR (0.x.0): 言語仕様の大きな変更 (BNF 構文変更、意味論の定義変更、再定義規則の変更)
- PATCH (0.0.x): 後方互換の機能追加、バグ修正、ドキュメント改善、誤字訂正

MAJOR (x.0.0) は、仕様が安定し 1.0.0 を宣言したのち、破壊的変更に用います。
