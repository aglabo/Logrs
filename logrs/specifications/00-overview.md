## Part 0: Overview

Logrs DSL は、**ドメインの構造を記述するための汎用言語** です。対象とするドメインを持たず、コマンド・変数・イベント・値集合・出力形式を定義する枠だけを提供します。特定ドメインの語彙は、コア仕様の上に置くプロファイルが定義します。プロファイルはコア仕様の確定後にあらためて作成する予定で、v0.8.0 時点では同梱していません。

### 半形式仕様としての位置づけ

本仕様は **llm 向けの半形式仕様 (semi-formal specification)** です。

形式的であるのは、記号体系、字句規則、ABNF による文法、意味論の制約規則です。これらは一意に解釈され、書かれたとおりに従うべきものです。

形式的でないのは、ブロックの本体に置かれる記述の内容、指示文が表す振る舞い、ドメインの意図です。これらは llm の自然言語理解に委ねられます。

**本 DSL は実行を目的としません。llm との認識共有を目的とします。** 処理系を実装するための厳密な言語定義ではなく、「どこまでが構造で、どこからが解釈か」の境界を llm に対して明示するための記述です。

### 設計原則

1. 統一形式 — すべてのブロックが `<ヘッダ> {{` … `}}` の 1 つの形に従う
2. 予約語ゼロ — 構造はすべて ASCII 記号が担い、英単語は一語も予約しない
3. 方向の明示 — 代入は `<-`、別名は `->`、状態遷移は `=>`、比較は `==` `!=` `<` `<=` `>` `>=` と、記号で役割と向きが読める
4. レイアウト非依存 — 空白・タブ・改行はすべて等価なトークンの区切りであり、行・字下げ・行数に文法的な意味はない
5. 構造と散文の分離 — 構造は記号が担い、自然言語による記述は必ず文字列リテラルか heredoc で囲む
6. ドメイン非依存 — コア仕様は対象ドメインを前提としない。ドメイン語彙はプロファイルが定義する
7. 識別子 — ASCII 限定 (`<identifier>`) / 日本語は別名 (`-> "..."`) で与える
8. 自己記述 — 意味論とプロファイルは、本 DSL の構文そのもので記述する。ただし **Syntax 層の生成規則は自己記述の対象外** とし、ABNF を正規のメタ言語とする ([1.1.1 メタ記法](./01-syntax-core.md#111-メタ記法-abnf--rfc-5234))。`%dsl` が担うのは言語の姿勢と、ABNF では表現できない制約である

### レイアウトに意味はない

本 DSL でもっとも強い構文上の決まりは、**レイアウトが一切の意味を持たない** ことです。

空白 (SP)・水平タブ (HTAB)・改行 (LF / CR) は、すべて等価なトークンの区切りです。種類・個数・位置のいずれも解釈を変えません。行頭・行末・字下げにもとづく規則はありません。

改行だけは、トークンの区切りに加えて 3 つの役割を持ちます。**これがすべてです。**

1. コメントを終端する — `;` から最初の改行までがコメント
2. 文字列リテラルの内部に現れてはならない — `"..."` `'...'` は改行をまたげない
3. heredoc の開始 `<<<` の直後の 1 個は、内容の開始を示す区切りとして捨てられる

3 つとも 1 つのトークンをどう切り出すかという規則です。文の区切り・ブロックの境界・値の終端は、いずれも改行とは無関係に文法から決まります。本仕様に「行」という単位はありません。

この帰結として、v0.3.0 にあった次の記法は v0.4.0 で廃止されました。

- `! 本文を確認する` のように終端を持たない自然文 (→ `! "本文を確認する"`。自然言語は文字列リテラルか heredoc でしか書けません)
- 改行を含む文字列リテラル (→ 単一行の `"..."` `'...'` と、複数行の heredoc に役割を分けました)
- 行末の `\` による行連結 (→ 不要)
- `{{` は行末、`}}` は行頭単独、という配置の決まり (→ 撤廃)
- 複数行形式とインライン形式の区別 (→ 統合)

詳細は [01-syntax-core の 1.1.3 字句規則](./01-syntax-core.md#113-字句規則) を参照してください。

### Backbone BNF

言語の骨格だけを示した、例示としての BNF です。

```abnf
; === トップレベル構造 ===
block    = header "{{" body "}}"

; === 拡張ポイント (重心) ===
header   = block-kind / command / variable / event / named-def
         / handler / compose / guard
body     = <opaque>  ; 内部構造は 01-syntax-core の 1.2 を参照

; === 種別は sigil で決まる (語ではない) ===
block-kind = "%" identifier          ; %dsl %define %rule %input %output %profile %example
command    = "/" identifier
variable   = [scope] ":" identifier
event      = "#" identifier
named-def  = label-name              ; sigil を持たない定義 (rule / constraint / field …)
scope      = "@" identifier          ; @session @scoped
handler    = "<-" "#" identifier     ; イベントを受ける
compose    = "+" "/" identifier ("^" / "$")
guard      = "(" [condition] ")"
```

**Backbone BNF の設計原則**:

1. 列挙しない: コマンド名や変数名を列挙せず、形式だけ示す (例: `command = "/" identifier`)
2. body を定義しない: `<opaque>` で内部構造を隠蔽し、中身に口を出さない
3. 分岐条件だけ残す: 拡張ポイント (header) は明示し、言語の重心を示す

**note**: この BNF は例示です。完全な構文受理を目的とせず、言語の **姿勢・重心・禁止領域** を llm へ示すよう設計されています。規範となる文法は [01-syntax-core の 1.2 統一 BNF](./01-syntax-core.md#12-統一-bnf) です。

**note**: `<opaque>` は「この領域は llm の自然言語理解に委ねる」ことを意味します。

### 最小使用例

```text
%input {{
  :buffer <- <<<
ここに対象テキストを記述します。
複数行を受け付けます。
<<<
}}

%define {{
  /run -> "処理を実行する" {{
    ! "buffer の内容を処理する"
    :session_phase <- done
  }}
}}
```

3 つのステップから成ります。

1. `%input` で入力を与える
2. `%define` でコマンド・変数・イベントを定義する
3. コマンドを呼び、`%output` が定める形で結果を得る

各ステップの詳細は後続のファイルで定義します。

### バージョン管理 (Semantic Versioning)

本仕様は 0.0.1 を起点とし、1.0.0 未満の開発段階にあります。

- MINOR (0.x.0): 言語仕様の大きな変更 (BNF 構文変更、意味論の定義変更、再定義規則の変更)
- PATCH (0.0.x): 後方互換の機能追加、バグ修正、ドキュメント改善、誤字訂正

MAJOR (x.0.0) は、仕様が安定し 1.0.0 を宣言したのち、破壊的変更に用います。
