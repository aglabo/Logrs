## Part 1: Syntax (続き)

### 1.3 メタブロック (構文的除外領域)

**設計意図**: DSL の定義そのものを **構文的に** 処理対象外とし、自己再帰リスクを根本的に防ぎます。

DSL を記述した文書を llm が読むとき、DSL の定義部分を「処理すべき対象」として扱ってしまうと、定義が自分自身に適用される再帰が起こります。メタブロックはこれを構文層で断ち切ります。

**構文**:

メタブロックは `%` を先頭に持つブロックであり、固有の文法を持ちません。[01-syntax-core の 1.2 統一 BNF](./01-syntax-core.md#12-統一-bnf) の `<block-kind>` と `<block>` がそのまま適用されます。

```abnf
; 再掲 (規範は 01-syntax-core の 1.2)
<block-kind> ::= "%" <identifier> *<identifier> *<modifier> [<alias>]
```

`%` に続く識別子は自由です。ドメインが必要とする種別を追加できます。次の 7 つは標準の種別です。

**block-type の意味**:

| タイプ     | 用途                                  | 例                             |
| ---------- | ------------------------------------- | ------------------------------ |
| `%dsl`     | DSL 構文定義 (BNF、意味論)            | Part 1, Part 2 の定義          |
| `%define`  | コマンド・変数・イベントの定義 / 合成 | モード定義、ハンドラ定義       |
| `%rule`    | 制約・規則定義 (rule / constraint)    | 動作規則・ガード条件           |
| `%input`   | 入力セクション (変数初期化)           | セッション変数の初期値設定     |
| `%output`  | 出力定義                              | 出力フォーマット定義           |
| `%profile` | ドメイン適用の宣言                    | プロファイルのメタ情報・方針   |
| `%example` | 例示 (登録されない定義)               | 用例・アンチパターン・対比例   |

標準の 7 つ以外の種別も、メタブロックとして同じ扱いを受けます。ただし `%example` だけは扱いが異なります ([`%example` — 登録されない例示](#example--登録されない例示))。

**note**: v0.6.0 まで本節には `<meta-block>` `<block-type>` `<block-content>` という独自の BNF がありました。種別を 6 つに閉じており、[01-syntax-core](./01-syntax-core.md) の `<block-kind>` が持つ第 2 識別子・`<modifier>`・`<alias>` を欠いていたため、v0.7.0 で削除し 01 への参照に置き換えました。規範となる文法は 01 だけが定めます。

**note**: v0.3.0 の `%macro` は `%define` に改名しました。「マクロ」という語がレビュー用テンプレート集という含意を持っていたためで、役割は変わりません。`%policy` は `%profile` に統合しました。

使用例:

```text
%define {{
  ; この領域は llm の処理対象外

  :acceptance {{
    pending -> "受付中"
    active  -> "処理中"
    :initial_acceptance <- pending
  }}

  /begin {{
    :buffer <- _
  }}

  /end {{
    ! "buffer の内容を確定する"
  }}
}}

; この Markdown 説明文はメタブロックの外側なので処理対象
```

**acceptance 説明**: `pending` は入力受付状態、`active` は処理実行状態です。

**重要な特性**:

1. 構文的除外: `%<type> {{` … `}}` の内側は llm の処理対象から除外される
2. 指摘禁止: 誤字脱字・曖昧表現を含め、内容に対する一切の指摘を禁止
3. スコープ: ブロック外の地の文だけが処理対象
4. 定義登録: 内容を「定義」として登録するかどうかは **種別ごとに定まる** (次表)

**種別ごとの登録可否**:

| block-kind             | 構文解析 | 定義登録   | 地の文としての処理 |
| ---------------------- | -------- | ---------- | ------------------ |
| `%example`             | する     | **しない** | しない             |
| それ以外のすべての種別 | する     | **する**   | しない             |

v0.6.0 までは全種別が一律に登録対象でした。v0.7.0 で `%example` を分離しています。

### `%example` — 登録されない例示

**設計意図**: 「これは例である」を構文層で表明し、例示コードが本物の定義として登録されるのを防ぎます。

仕様書や DSL 定義は、用例・アンチパターン・対比例を示すために、定義とまったく同じ形のコードを書きます。`%example` がないと、それらは外側の定義ツリーに登録され、**禁止例がそのまま有効な定義になります**。`%example` はこの区別を担います。

`%example` は `<block-kind>` そのものであり、新しい記法を持ちません。`%example` に続く識別子は何個でも置けるため ([`<block-kind>`](./01-syntax-core.md#12-統一-bnf))、それと [`<alias>`](./01-syntax-core.md#12-統一-bnf) で例の性格を示せます。

```text
%example forbidden normal_flow -> "禁止: 通常フロー制御" {{
  <-#UserInputReceived {{
    :session_phase <- input
  }}
}}

%example permitted recovery {{
  <-#ProcessInterrupted {{
    :session_phase <- :previous_mode
  }}
}}
```

**`%example` の規則**:

1. 登録しない。内側のコマンド・変数・イベント・ハンドラ・合成・ラベル定義を、一切登録しません
2. 評価しない。内側の `constraint` / `rule` / ガードは、実行時の契約になりません
3. 再帰的に伝播する。入れ子のブロックにも 1 と 2 がおよびます。入れ子に `%define` や `%rule` が現れても登録されません
4. 参照は一方向。例示から外側の定義は参照できます。逆向きの参照は禁止です。外側から参照できると、登録したのと変わらなくなるためです

**note**: `%example` は heredoc の代わりではありません。heredoc は改行を含むテキストを値として持つための記法で、その本文に `<<<` を含められません ([01-syntax-core の heredoc](./01-syntax-core.md#heredoc))。DSL コードを含む例を heredoc に入れることはできないため、**例示は heredoc の外に、`%example` で囲んで書きます**。

**note**: 例が他の定義ブロックの内側にあるときは `%example` で囲んでください。独立したコードフェンスに置かれた断片は、フェンス自体が例示の枠として働くため、囲む必要はありません。

**除外の 2 区分**:

| 区分                 | 層     | llm の扱い                             | 定義登録 |
| -------------------- | ------ | -------------------------------------- | -------- |
| `%<type> {{` … `}}`  | 構文層 | 地の文として読まず、定義として取り込む | する     |
| `%example {{` … `}}` | 構文層 | 地の文として読まず、定義にもしない     | しない   |

メタブロックにより、自己再帰問題が根本的に解決されます。

**note**: メタブロックの範囲は `{{` と `}}` の対応だけで決まります。レイアウトは関係しません ([01-syntax-core の 1.1.3 字句規則](./01-syntax-core.md#113-字句規則))。
