## Part 1: Syntax

### 1.1 記号体系

本 DSL の記号は 2 つの層に分かれます。**メタ記法** は本仕様書が文法を説明するために使う記号 (RFC 5234 ABNF 由来) であり、**オブジェクト言語の記号** は DSL そのものを書くために使う記号です。この 2 つを混同しないでください。

本節と [1.2 統一 BNF](#12-統一-bnf) は本仕様の **規範部** です ([00-overview の規範と例示](./00-overview.md#規範と例示))。

#### 1.1.1 メタ記法 (ABNF / RFC 5234)

本仕様書の BNF 定義中でのみ使われます。DSL の記述には現れません。

| 記号        | 意味           | 例                     |
| ----------- | -------------- | ---------------------- |
| `<name>`    | 非終端記号     | `<command>`, `<value>` |
| `::=`       | 定義           | `<A> ::= <B>`          |
| `/`         | 選択           | `A / B`                |
| `[xxx]`     | 省略可能       | `[<option>]`           |
| `*xxx`      | 0 回以上の繰返 | `*<statement>`         |
| `1*xxx`     | 1 回以上の繰返 | `1*<var-name>`         |
| `"..."`     | リテラル       | `"{{"`                 |
| `; comment` | コメント       | `; トップレベル`       |

#### 1.1.2 オブジェクト言語の記号

DSL を書くときに使う記号です。**すべての構造は記号が担い、英単語は一語も予約されていません**。したがって任意の英単語をラベル名・識別子として自由に使えます。

構文として定義される記号は、すべて ASCII 文字だけで構成します。`≠` `≤` `≥` のような非 ASCII の記号は、それがどれだけ読みやすくても構文には採用しません。入力手段や文字コードの設定によらず書けること、および処理系の字句解析を単純に保つことを優先します。この制限がおよぶのは記号だけです。ラベル名・識別子・文字列リテラルの中身は対象外で、本仕様書の地の文が日本語であることもこの制限とは無関係です。

##### ブロック

| 記号 | 役割         | 例           |
| ---- | ------------ | ------------ |
| `{{` | ブロック開始 | `%define {{` |
| `}}` | ブロック終端 | `}}`         |

`{{` と `}}` をどこに置くかに文法上の決まりはありません。改行して書いても 1 つの区切りにまとめて書いても、同じ構文木になります。

##### 演算子

| 記号 | 役割                     | 例                          |
| ---- | ------------------------ | --------------------------- |
| `<-` | 代入 (右辺 → 左辺)       | `:buffer <- ""`             |
| `->` | 別名・対応付け           | `pending -> "受付中"`       |
| `=>` | 状態遷移・写像           | `pending => active`         |
| `==` | 比較 (等値)              | `:session_phase == waiting` |
| `!=` | 比較 (非等値)            | `status != ready`           |
| `<`  | 比較 (小なり / 数値のみ) | `(:retry_count < 3) {{`     |
| `<=` | 比較 (以下 / 数値のみ)   | `(:retry_count <= 3) {{`    |
| `>`  | 比較 (大なり / 数値のみ) | `(:char_count > 500) {{`    |
| `>=` | 比較 (以上 / 数値のみ)   | `(:char_count >= 500) {{`   |
| `!`  | 論理否定 (not)           | `(!:flag) {{`               |
| `&`  | 論理積 (and)             | `(:a == 1 & :b == 2) {{`    |
| `\|` | 論理和 (or)              | `(:a == 1 \| :b == 2) {{`   |
| `_`  | 空値・未定義             | `:buffer <- _`              |

`!` `&` `|` は条件式の中だけで論理演算子として働きます。本体では `!` は実行と発火を表します ([1.1.3 字句規則](#113-字句規則))。

##### sigil (対象種別)

| 記号 | 役割         | 例                                                     |
| ---- | ------------ | ------------------------------------------------------ |
| `%`  | ブロック種別 | `%dsl` `%define` `%rule` `%input` `%output` `%profile` |
| `/`  | コマンド     | `/begin` `/end`                                        |
| `:`  | 変数         | `:buffer` `:session_phase`                             |
| `#`  | イベント     | `#ProcessFailed`                                       |
| `@`  | スコープ     | `@session` `@*`                                        |

##### 動作・合成・分岐

| 記号            | 役割               | 例                                   |
| --------------- | ------------------ | ------------------------------------ |
| `!`             | 実行 (指示文)      | `! "入力を確定する"`                 |
| `!#name (k: v)` | イベント発火       | `!#ProcessFailed (error: "missing")` |
| `<-#name {{`    | イベントハンドラ   | `<-#ProcessFailed {{`                |
| `+/cmd ^ {{`    | コマンドへの合成   | `^` = 前 / `$` = 後                  |
| `+name`         | 付加指定           | `%output record +location {{`        |
| `(<条件>) {{`   | 条件分岐           | `(:link == "") {{`                   |
| `() {{`         | 既定分岐 (else)    | `() {{`                              |
| `--name: value` | オプション         | `/run --mode: strict`                |
| `(k: v)`        | ペイロード・型指定 | `#ProcessFailed (error: text)`       |
| `; …` + 改行    | コメント           | `; ここは注釈`                       |

##### 値リテラル

| 記法    | 役割                          | 例                       |
| ------- | ----------------------------- | ------------------------ |
| `"..."` | 文字列 (エスケープ解釈あり)   | `"対象テキスト"`         |
| `'...'` | 生文字列 (エスケープ解釈なし) | `'C:\path\to'`           |
| `<<<`   | heredoc (raw)                 | Markdown・箇条書き・長文 |

#### 1.1.3 字句規則

##### 空白類はすべて等価な区切りである

**空白 (SP, %x20)・水平タブ (HTAB, %x09)・改行 (LF, %x0A / CR, %x0D) は、すべて等価なトークンの区切りです。** この 4 種をまとめて空白類と呼びます。

- 空白類の **種類** に意味はありません。空白とタブと改行を入れ替えても、解釈は変わりません。
- 空白類の **個数** に意味はありません。1 個でも 100 個でも、区切りが 1 つあることを表します。
- 空白類の **位置** に意味はありません。行頭・行末・字下げといったレイアウト上の概念は、本 DSL の文法には存在しません。

ソーステキストはトークンの列であり、空白類はトークンとトークンの境界を示すためだけに存在します。次の 3 つはすべて同一の構文木になります。

```text
%rule link_check {{
  (:link == "") {{
    ! "リンクが未設定であると報告する"
  }}
}}
```

```text
%rule link_check {{ (:link == "") {{ ! "リンクが未設定であると報告する" }} }}
```

```text
%rule
link_check
{{ (:link
== "") {{ ! "リンクが未設定であると報告する" }} }}
```

3 つめは読みにくいだけで、誤りではありません。読みやすさのためにどう配置するかは [05-heuristics のスタイル](./05-heuristics.md#style-guidelines---スタイル) が扱う慣習の問題であり、文法の問題ではありません。

##### 改行が特別扱いされる 3 か所

改行はトークンの区切りとして空白・タブと等価ですが、それに加えて次の 3 つの役割を持ちます。**これがすべてです。**

| 場所                              | 改行の役割                                                           |
| --------------------------------- | -------------------------------------------------------------------- |
| [コメント](#コメント)             | `;` から最初の改行までがコメント。改行が終端になる                   |
| [文字列リテラル](#文字列リテラル) | `"..."` `'...'` の内部に現れてはならない。リテラルは改行をまたげない |
| [heredoc](#heredoc)               | 開始 `<<<` の直後の 1 個は、内容の開始を示す区切りとして捨てられる   |

3 つとも **1 つのトークンの内部をどう切り出すかという規則** です。トークンとトークンの関係 — 文の区切り、ブロックの境界、値の終端 — には一切影響しません。そこに改行が何個あっても、1 個もなくても、解釈は変わりません。

本仕様に「行」という単位はありません。行頭・行末・字下げ・行数にもとづく規則もありません。上の 3 つは、改行という 1 文字が持つ役割であって、行という単位の導入ではありません。

##### 区切りが必要な位置

隣接するトークンの境界が記号だけでは決まらないとき、区切りとして空白類が 1 個以上必要です。具体的には次の 2 つです。

1. 識別子・数値・真偽値どうしが隣接するとき (`enum priority` の `enum` と `priority`)
2. **中置演算子 `<-` `->` `=>` `==` `!=` `<` `<=` `>` `>=` `&` `|` の前後**

2 が必要なのは、識別子がハイフンを含みうるためです ([1.2 統一 BNF](#12-統一-bnf) の `<identifier>`)。`a->b` と書くと `a-` までが識別子として切り出され、意図した `a` `->` `b` になりません。前後を空白類で区切れば曖昧になりません。ここでいう空白類には改行も含まれるため、長い式は演算子の前後で改行して構いません。

それ以外の位置では区切りは任意です。`%rule link_check{{` や `(!:flag)` のように、sigil や括弧が境界を決める位置では空白類を省けます。

##### 最長一致

記号は最長一致で切り出します。2 文字以上の演算子は、その先頭 1 文字からなる演算子より先に取ります。具体的な優先順序は次のとおりです。`<<<` は `<=` `<-` `<` より先に取ります。`<=` と `<-` は `<` より先に、`>=` は `>` より先に、`!=` は `!` より先に取ります。`==` と `=>` はどちらも 2 文字で確定します。

`==` は **比較** であって代入ではありません。代入は `<-` だけが担います。単独の `=` は演算子ではなく、そこに現れた `=` を構文エラーとして扱います。

##### 記号の多義性は文脈で決まる

`( )` には 3 つの用途がありますが、文脈で一意に決まります。`{{` の直前なら条件ガード (`(:link == "") {{`)、名前の直後ならペイロードや型の指定です (`#ProcessFailed (error: text)`)。条件ガードの内側はすべて条件式なので、そこに現れる `( )` は論理演算のグループ化です。

`+` の意味は直後の sigil で決まります。`+/cmd` は合成、`+location` は付加指定です。

`!` の意味も文脈で決まります。条件式の中なら論理否定、文が始まる位置なら実行 (`! <文字列>`) か発火 (`!#name`) です。

`<<<` を heredoc の開始と解釈するのは値の位置だけです。コマンドのパラメータを表す `<:target>` の `<` とは文脈で区別されるため、曖昧にはなりません。同じ区別は比較演算子の `<` にもおよびます。`<` `<=` `>` `>=` を演算子として解釈するのは条件式の中だけで、コマンド定義のヘッダに現れる `<...>` はパラメータです。

引用符付きの記号 (`"{{"`) はオブジェクト言語、素のままはメタ記法を表します。この規則により、`/` (ABNF の選択 vs コマンド sigil) が曖昧になりません。

`<>` `[]` `..` はコマンド定義のパラメータを説明するメタ構文であって、オブジェクト言語の記号ではありません。

##### コメント

コメントは `;` で始まり、**最初の改行で終わります**。

```text
:buffer <- _        ; 入力バッファを空にする
```

コメントは字句層で空白類 1 個に置き換えられます。トークンの境界として働き、それ以外の意味を持ちません。したがって区切りが必要な位置に置けます。

コメントの中に `;` を書いても終端にはなりません。終端は改行だけです。改行を欠いたままソースが終わったときは、その位置でコメントを閉じます。文字列リテラルと heredoc の内部にある `;` は、コメントの開始ではなくリテラルな文字です。

##### 文字列リテラル

文字列リテラル (`"..."` `'...'`) と heredoc の内部には、字句規則がおよびません。空白とタブは区切りではなく内容の一部であり、`!` `&` `|` `(` `)` `;` を記号として解釈しません。`(:sep == "&")` の `&` はリテラルな文字です。

**文字列リテラルは改行をまたげません。** `"..."` `'...'` の内部に改行が現れたら構文エラーです。開き引用符に対応する閉じ引用符は、同じ改行の手前になければなりません。この制限により、閉じ忘れがソースの末尾まで飲み込まれず、その場でエラーになります。

複数行のテキストは [heredoc](#heredoc) で書きます。文字列リテラルは短い単一行の値、heredoc は構造を持つ長文、という役割分担です。

`"..."` の中では次の 5 種のエスケープシーケンスを解釈します。

| 記法 | 意味                |
| ---- | ------------------- |
| `\n` | 改行 (LF, %x0A)     |
| `\t` | 水平タブ (HT, %x09) |
| `\\` | バックスラッシュ    |
| `\"` | 二重引用符          |
| `\'` | 単一引用符          |

この 5 種以外の `\` + 文字は構文エラーです。`"..."` の中には素の `'` をそのまま書けるため、`\'` は許容されますが必須ではありません。

`"..."` の中で改行を表したいときは `\n` を使います。素の改行は書けません。

`'...'` は生文字列であり、エスケープを解釈しません。`\` は通常の文字として扱われるため、パスや正規表現をそのまま書けます (`'C:\path\to'`)。ただし `'` 自体は含められません。必要なときは `"..."` と `\'` を使ってください。エスケープを解釈しないため、生文字列では改行を表現する手段がありません。改行を含む生テキストは heredoc で書きます。

##### heredoc

heredoc は値の位置に置いた `<<<` で始まり、次に現れる `<<<` で終わります。本文はエスケープを解釈せず、改行を含む空白類をそのまま保持します。**複数行のテキストを書ける唯一の記法です。** 加工なしで Markdown や構造化テキストを書くために使います。

開始の `<<<` の直後に空白類が続く場合、そのうち最初の改行までを区切りとして捨てます。捨てないと、`<<<` の次から本文を始めたときに先頭が必ず空行になるためです。改行を伴わずに本文が始まるなら、`<<<` の直後から本文です。終端側では捨てません。`<<<` の直前の空白類は本文に含まれます。

```text
:buffer <- <<<
# 見出し

  字下げも空行もそのまま保持されます。
<<<
```

本文に `<<<` を含めることはできません。終端の `<<<` を欠いたままソースが終わった場合は構文エラーです。

##### 自由文の廃止

v0.3.0 までは、実行文 `! 本文を確認する` や条件式の項として、終端を持たない自然言語のテキストを直接書けました。これは改行が終端として働くことに依存した記法です。改行が区切りの一種になった v0.4.0 では成立しないため、**自然言語による記述はすべて文字列リテラルまたは heredoc で囲みます**。

```text
! "入力を確定する"      ; v0.4.0
! 入力を確定する        ; v0.3.0 の記法。構文エラー
```

この変更により、「構造は記号が担い、散文は引用で区切る」という境界が字句層で明示されます。

#### 1.1.4 条件分岐

条件分岐は、条件式をガードとして持つブロックです。条件式は必ず `(` `)` で囲み、`{{` の直前に置いてください。この位置の `( )` はガードとして一意に解釈されます ([1.1.3 字句規則](#113-字句規則) を参照)。

条件式の評価結果が true のとき、直後のブロックの本体を実行します。false のときは本体を実行せず、次の文へ進みます。

条件式の項は、比較 (`==` `!=` `<` `<=` `>` `>=`)、変数、`true` / `false`、文字列リテラルのいずれかです。項は論理演算子で合成できます。`!` が論理否定 (not)、`&` が論理積 (and)、`|` が論理和 (or) を表します。`!` は直後の 1 項だけに作用し、`&` と `|` より強く結合します。`&` と `|` の優先順位に上下はありません。結合を明示するには `( )` を使ってください。

条件式は左から順に評価します。`&` の直前で左辺が false なら、以降を評価せず false を返します。`|` の直前で左辺が true なら、以降を評価せず true を返します。どちらでもなければ、右辺の値がそこまでの結果になります。この打ち切りは、それを含むもっとも内側の `( )` グループで止まります。`( )` に囲まれていなければ、条件式全体を打ち切ります。

したがって `&` と `|` を混在させた条件式では、左から 2 項ずつ畳み込んだ式と異なる結果になることがあります。意図した結合は `( )` で明示してください。

```text
false & x | true    → false   ; & の左が false → 条件式全体を打ち切る
(false & x) | true  → true    ; 打ち切りはグループの中で止まる
true | x & false    → true    ; | の左が true → 条件式全体を打ち切る
(true | x) & false  → false   ; グループで止まったあと & false を評価する
!a & b              ≡ (!a) & b
```

二項演算子の左辺または右辺がない条件式、`!` のうしろに項がない条件式、`( )` が対応していない条件式は構文エラーです。

`()` のように条件式を持たないガードは、`otherwise` / `else` にあたる既定分岐です。先行する分岐がすべて false のときに本体を実行します。

同じブロックの中に連続して現れるガードの並びを分岐列と呼びます。分岐列は先頭から評価し、最初に true となった分岐の本体だけを実行します。残りの条件式は評価しません。既定分岐は分岐列を終端します。既定分岐のうしろにさらにガードが現れた場合、それは新しい分岐列の先頭です。

「連続して現れる」はレイアウトではなく、**ガード付きブロックのあいだに他の文が挟まらないこと** で決まります。

```text
%rule link_check {{
  (:link == "")        {{ ! "リンクが未設定であると報告する" }}
  (:link != :expected) {{ ! "リンクが一致しないと報告する" }}
  ()                   {{ ! "報告しない" }}
}}
```

先行する分岐を持たない既定分岐は構文エラーです。ブロックの先頭や、直前の文がガード付きブロックではない位置の `()` がこれにあたります。

**note**: 等値比較 `==` `!=` は値を文字列として比べます。大小比較 `<` `<=` `>` `>=` は両辺を数値として解釈してから比べます。数値として解釈できるのは、符号なしの整数 (`500`)、負の整数 (`-3`)、および小数点をひとつ持つ実数 (`1.5` `-0.25`) の形式だけです。指数表記・桁区切り・単位や記号を伴う表記は解釈できません。どちらかの辺が解釈できない場合はエラーです。**文字列どうしの大小比較は定義しません。**

**note**: 大小比較は値の型を増やしません。数値としての解釈は比較のあいだだけ行われるもので、変数に格納される値は文字列のままです。[04-semantics-execution](./04-semantics-execution.md) の `数値型は存在しない` と `すべての値は文字列である (単一型システム)` はそのまま成立します。

**note**: 論理結合は散文ではなく `!` `&` `|` で書きます。条件式の項に置く文字列リテラルは、内容が評価対象であって論理構造を表しません。

**note**: 論理演算子は条件式の判定結果に作用します。変数に格納できる値の型を増やすものではないため、[04-semantics-execution](./04-semantics-execution.md) の `真偽型は存在しない` はそのまま成立します。

**note**: ここでいう条件分岐は、ガードによる静的な分岐です。[04-semantics-execution のイベントシステム](./04-semantics-execution.md#イベントシステム) がイベントハンドラに対して禁じている `conditional_branching` は、ペイロードの内容に応じて `:session_phase` の遷移先を動的に選ぶ処理を指すもので、別の概念です。

### 1.2 統一 BNF

本 DSL のトークン列に対する文法を ABNF 記法 (RFC 5234) で定義します。

空白類とコメントは字句層でトークンの区切りとして処理され、以下の文法には現れません ([1.1.3 字句規則](#113-字句規則))。ただし文字列リテラルと heredoc の内部は字句層の対象外です。

```abnf
; ============================================================
; Logrs DSL Unified Grammar - v0.5.1
; 以下はトークン列に対する文法である。
; 空白類 (SP / HTAB / LF / CR) とコメント (";" から改行まで) は
; 字句層で区切りとして除去され、本文法には現れない。
; 改行が特別扱いされるのはコメントの終端、文字列リテラルの禁止文字、
; heredoc の開始直後の 3 か所のみ (1.1.3 を参照)。
; ============================================================

; --- トップレベル ---
<unit>            ::= *<block>
<block>           ::= <header> "{{" <body> "}}"
<header>          ::= <block-kind> / <def-target> / <handler> / <compose> / <guard>

; --- ブロック種別 (容器) ---
<block-kind>      ::= "%" <identifier> [<identifier>] *<modifier> [<alias>]
                      ; 標準: %dsl / %define / %rule / %input / %output / %profile

; --- 定義ターゲット ---
<def-target>      ::= <command> / <variable> / <event> / <named-def>
<command>         ::= "/" <identifier> *<param> *<option> [<alias>]
<variable>        ::= [<scope>] <var-name> ["<-" <value>] [<alias>]
<event>           ::= "#" <identifier> [<payload>] [<alias>]
<named-def>       ::= <label-name> [<payload>] *<modifier> [<alias>]
                      ; sigil を持たない定義。例: enum priority / Record -> "…" /
                      ;   location -> "文章位置" / fallback ValidationFailed /
                      ;   rule composition constraint composition
<label-name>      ::= <identifier> *(<identifier> / <number>)
                      ; 見出し語の並び。先頭は識別子。例: constraint status values /
                      ;   test_case 1

<scope>           ::= "@" <identifier> / "@*"       ; 標準: @session
<var-name>        ::= ":" <identifier>
<alias>           ::= "->" <string-literal>
<payload>         ::= "(" <pair> *("," <pair>) ")"
<pair>            ::= <identifier> ":" (<type> / <value>)
<type>            ::= "text" / "number" / "boolean" / "object" / <identifier>
<modifier>        ::= "+" <identifier>              ; 例: +location

; --- ハンドラ・合成・ガード ---
<handler>         ::= "<-" "#" <identifier>
<compose>         ::= "+" "/" <identifier> ("^" / "$")
<guard>           ::= "(" [<condition>] ")"     ; 条件式なし = 既定分岐
<condition>       ::= <term> *(("&" / "|") <term>)  ; "&" と "|" は同一優先度・左から順に評価
                      ; 短絡と打ち切りの範囲は 1.1.4 を参照 (ABNF では表現しない)
<term>            ::= ["!"] <atom>                  ; "!" は直後の 1 項のみに作用
<atom>            ::= "(" <condition> ")" / <comparison> / <var-name>
                    / <boolean> / <string-literal>

; --- 本体 ---
<body>            ::= *(<statement> / <block>)
<statement>       ::= <assign> / <emit> / <exec> / <transition>
                    / <alias-line> / <label-def> / <comparison>
<assign>          ::= (<var-name> / <scope>) "<-" <value>
<emit>            ::= "!" "#" <identifier> [<payload>]
<exec>            ::= "!" <text-literal>            ; 指示文。終端を持つリテラルに限る
<transition>      ::= <operand> "=>" <operand>      ; 状態遷移および写像
<comparison>      ::= <equality> / <ordering>
<equality>        ::= <operand> ("==" / "!=") <operand>  ; 比較 (代入ではない)
<ordering>        ::= <num-operand> ("<" / "<=" / ">" / ">=") <num-operand>
                      ; 大小比較。両辺を数値として解釈する (1.1.4 を参照)
<num-operand>     ::= <var-name> / <number>
                      ; <var-name> を許すのは、値が数値の形式かどうかが
                      ; 実行時にしか決まらないため
<operand>         ::= <var-name> / <identifier> / <value>
<alias-line>      ::= <identifier> "->" <string-literal>
<label-def>       ::= <label-name> ":" <value>      ; 値は省略できない。
                      ; 値を持たない見出しはブロック (<named-def> "{{" … "}}") で書く
                      ; <named-def> との区別には ":" / "{{" までの先読みを要する

; --- コマンドのパラメータ・オプション ---
<param>           ::= "<" [":"] <identifier> ">"
                    / "[" "<" [":"] <identifier> ">" ".." "]"
<option>          ::= "--" <identifier> ":" (<identifier> / <string-literal>)

; --- 値 ---
<value>           ::= <text-literal> / <number> / <boolean> / <var-name>
                    / <identifier> / "_"
<text-literal>    ::= <string-literal> / <heredoc>
<string-literal>  ::= <quoted-string> / <raw-string>
<quoted-string>   ::= DQUOTE *<dq-char> DQUOTE      ; エスケープを解釈する
<dq-char>         ::= <escape> / %x20-21 / %x23-5B / %x5D-7E / WSP / CJK
                      ; `"` (%x22) と `\` (%x5C) を除く。LF / CR は含めない
                      ; (文字列リテラルは改行をまたげない。改行は `\n` で書く)
<escape>          ::= %x5C (%x6E / %x74 / %x5C / DQUOTE / SQUOTE)
                      ; %x6E = n / %x74 = t。ABNF の引用文字列は大文字小文字を
                      ; 区別しないため、`\N` `\T` を排除する目的で %x で指定する
<raw-string>      ::= SQUOTE *<sq-char> SQUOTE      ; エスケープを解釈しない
<sq-char>         ::= %x20-26 / %x28-7E / WSP / CJK        ; `'` (%x27) を除く
                      ; LF / CR は含めない。生文字列も改行をまたげない
<heredoc>         ::= "<<<" *<hd-char> "<<<"   ; 複数行テキストを書ける唯一の記法
<hd-char>         ::= VCHAR / WSP / LF / CR / CJK
                      ; "<<<" を含まない (ABNF では表現できない制約)
                      ; 開始 "<<<" の直後の改行 1 個は本文に含まない (1.1.3 を参照)
<number>          ::= ["-"] 1*DIGIT ["." 1*DIGIT]  ; 整数または小数 (指数表記なし)
<boolean>         ::= "true" / "false"
<identifier>      ::= (ALPHA / "_") *(ALPHA / DIGIT / "_" / "-" / CJK)

; --- Location 型 ---
<section-id>      ::= <identifier> ["[" <number> "]"]
<node-index>      ::= <node-type> "[" <number> "]" [".sentence[" <number> "]"]
<node-type>       ::= "paragraph" / "list_item" / "heading" / "table" / "figure"

; --- ABNF 基本定義 (RFC 5234 準拠) ---
; ALPHA  = %x41-5A / %x61-7A           ; A-Z / a-z
; DIGIT  = %x30-39                     ; 0-9
; DQUOTE = %x22                        ; "
; SQUOTE = %x27                        ; '
; HTAB   = %x09                        ; タブ
; SP     = %x20                        ; 空白
; WSP    = SP / HTAB                   ; 空白類 (水平)
; VCHAR  = %x21-7E                     ; 可視文字
; CR     = %x0D                        ; 復帰
; LF     = %x0A                        ; 改行
; CJK    = %x3040-309F / %x30A0-30FF / %x4E00-9FFF  ; ひらがな/カタカナ/漢字
```

**キーワード消滅にともなう統合**: v0.1.1 にあった `<status-def>` `<priority-def>` `<location-def>` `<rule-def>` `<field-def>` `<clearby>` `<constraint-clause>` は、キーワードが無くなったことで文法的に区別できなくなったため、汎用の `<label-def>` に統合しました。値集合の検証は文法層ではなく意味論層が担います ([03-semantics-core の値集合の意味論的検証](./03-semantics-core.md#値集合の意味論的検証))。

**v0.4.0 での統合**: v0.3.0 にあった `<logical-line>` `<content>` (物理行から論理行への前処理)、複数行形式とインライン形式に分かれていた `<block>`、終端を持たない `<exec>` `<nl-text>` `<label-line>` は、レイアウトが文法的な意味を失ったことですべて不要になりました。`<comment>` は文法から外れ、字句層の規則になりました。

```text
%rule {{

  bnf-formality {{
    rule: <<<
本 BNF は以下の特性を持つ:
  - 厳密な BNF ではなく、llm の理解を支援する構造契約である
  - 実行順序・スコープライフタイム・モード遷移は part 2 で定義される
  - 文法的正当性と実行時意味は分離されている
<<<
  }}

}}
```
